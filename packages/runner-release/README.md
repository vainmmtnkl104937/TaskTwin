# `@tasktwin/runner-release`

Framework-independent contracts and deterministic decisions for TaskTwin Runner
releases.

The package separates product SemVer from the compatibility axes that control
execution: run protocol, Workflow definition schema, local Runner-state schema,
and Local Secret Vault schema. A newer product version is not automatically
compatible, and an older version is not automatically unsafe. The signed
release declaration controls upgrade preflight, while the deployed Control
Plane policy and authenticated heartbeat identity control job eligibility.

## Trust boundary

The package validates release identities, artifact descriptors, canonical
manifests, detached Ed25519 signature documents, trusted public-key descriptors,
Control Plane policies, and upgrade-preflight inputs. It contains no filesystem,
Node crypto, GitHub, Windows, Prisma, NestJS, React, Playwright, or service-manager
code. Applications inject hashes, verified signatures, artifact observations,
and local schema headers at their boundaries.

The manifest never supplies a trusted public key. `keyId` is resolved only
against an application-compiled public-key set. Production private keys belong
only in the protected CI signing environment. Rotation requires an overlap
release that trusts both the retiring and replacement public keys before signing
switches to the replacement.

The repository's production trusted-key registry is intentionally empty and
fails closed. Tests and dry runs inject ephemeral public keys at their call
boundaries; those keys are not compiled into the Runner. A production release
requires a reviewed public-key registry entry and the matching protected CI
private-key credential. No production private key is committed or generated by this
package.

## Verification order

1. Strictly parse manifest and signature.
2. Resolve the detached signature key ID from the trusted registry.
3. Canonicalize the validated manifest with TaskTwin canonical JSON.
4. Recompute its SHA-256 and verify the detached Ed25519 signature.
5. Select the exact target artifact.
6. Match its file name, exact size, and SHA-256.

Every mismatch fails closed. There is no ignore-integrity or arbitrary-key
override.

## Upgrade preflight

`evaluateUpgradePreflight` is pure and returns `compatible`,
`migration_required`, `unsupported`, or `downgrade_blocked`. The caller must
verify the target release first and supply bounded, read-only observations of the
installed state. Preflight never migrates, rewrites, or downgrades state.

Session 31 publishes Windows x64 ZIP artifacts only. The platform contracts are
explicit so future targets can be versioned without weakening the current
release allowlist.
