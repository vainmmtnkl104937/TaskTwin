# v1.0.0-rc.1 — Release Candidate Notes

This is the first release candidate of the TaskTwin browser-first MVP. It is
the build on which User Acceptance Testing is performed. The candidate is
stabilization only; it adds no product surface and changes no security,
privacy or policy invariants.

## What ships

TaskTwin v1.0.0-rc.1 carries the full V1 feature set delivered through
Session 39:

- Chrome extension recording with privacy-bounded event capture, semantic
  locator bundles, deterministic recording-to-Draft conversion and immutable
  recording artifacts.
- Authenticated Draft workflow editor with variables, value sources, secret
  references, ephemeral Extract outputs, deterministic Verify steps, Approval
  gates, conservative retry and attended repair, and privacy-filtered locator
  repair proposals.
- Local Runner pairing, heartbeat, separate credential, Windows Service mode
  with DPAPI-NG native unlock, signed Windows x64 releases with explicit
  protocol, schema and local-state compatibility, local update and rollback
  controller, trusted release catalog and controlled staged fleet rollouts.
- Control Plane: short-lived access-token authentication, immutable workflow
  versions, Workspace execution policy with deny precedence, deterministic
  scheduler with DST-safe IANA timezone occurrences, encrypted run inputs,
  append-only hash-chained audit trail, in-app operational alerts, and
  privacy-safe operational telemetry.
- Production Control Plane Docker Compose baseline with separate Web, API,
  Scheduler, Notification Worker, migration job and PostgreSQL services,
  read-only root filesystems, dropped Linux capabilities and exact-origin
  browser CORS.

## What this session adds

Session 40 is a stabilization pass for `v1.0.0-rc.1`. It ships:

- The product release tag `v1.0.0-rc.1` recorded in `VERSION` and documented in
  `docs/RELEASE.md`.
- A repeatable V1 UAT checklist (`docs/uat/v1-primary.md`).
- A manual smoke runbook for operators (`docs/uat/v1-smoke-test.md`).
- A known-issues register (`docs/uat/known-issues-v1.0.0-rc.1.md`).
- Severity definitions (`docs/severity.md`).
- First-time runner onboarding guide (`docs/onboarding/v1-runner.md`).
- Web UX fixes: login expired banner, Workspaces welcome checklist, loading
  skeletons on the heaviest pages, hardened root error page, normalized
  status labels in the audit verifier, Runner release catalog, Operations
  dashboard and Fleet view, a Fleet→Rollouts shortcut, and a real policy
  digest in the Draft editor evaluation.
- Documentation maintenance updates (`docs/ai/CURRENT_STATE.md`,
  `docs/ai/SESSION_INDEX.md`).

## What this session deliberately does not change

- No new product feature, dependency or public API.
- No change to authentication, authorization, RBAC, Runner revocation or
  run-lease behaviour.
- No change to audit, alerts, telemetry, secret storage, release signing or
  fleet rollout semantics.
- No change to the Production Control Plane Docker Compose topology beyond
  pre-existing baselines.

## Operators

- Testers: run `docs/uat/v1-smoke-test.md` against a fresh Compose stack.
  Record pass/fail per scenario in `docs/uat/v1-primary.md`.
- Release managers: the candidate is cut from the branch that contains the
  `v1.0.0-rc.1` `VERSION`. Promotion to `v1.0.0` requires zero open
  V1 release blockers (see `docs/severity.md`).

## Known limitations carried forward

See `docs/uat/known-issues-v1.0.0-rc.1.md` for the live register. Limitations
inherited from earlier sessions remain; the RC does not resolve them and they
are not V1 release blockers.
